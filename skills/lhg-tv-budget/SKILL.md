# lhg-tv-budget：旅行预算编制方法论

## 1. 何时使用

- 总预算定了，不知道钱怎么分到交通/住宿/餐饮/门票上时
- 预算表做出来，分项加总和总数对不上时
- 怀疑预算结构不合理（住宿太贵/没留应急）时

不适用：日行程规划（用 `lhg-tv-plan`）、POI 筛选（用 `lhg-tv-poi`）。

**红线**：本 skill 只做预算框架估算。机票/酒店实时价格与库存请以官方平台为准自行核实，
不许给出"实时价格""当前 X 元""最低价保证"类承诺。

## 2. 输入与输出

**输入**：总预算 + 人数 + 天数 + 口径（是否含往返大交通）。

**输出**：六分项预算表，分项求和=总预算，每项写清计算过程。

## 3. 六分项框架

| 分项 | 包含内容 | 占比参考 |
|---|---|---|
| 交通 | 往返大交通 + 当地市内交通 | 20-30% |
| 住宿 | 酒店/民宿：晚数×档位单价 | 30-40% |
| 餐饮 | 天数×人均餐标×人数 | 15-25% |
| 门票 | POI 门票加总（免费写 0） | 5-15% |
| 购物 | 纪念品/特产（可选分项） | 0-10% |
| 应急预留 | 改签/打车/买药等意外 | ≥5% |

占比是参考不是教条：穷游交通占比高正常，度假住宿占比高正常。
但两条铁律不变：**住宿单项不许超 60%**，**应急预留不许低于 5%**。

## 4. 编制顺序：先确定的，后弹性的

1. **门票**：从 POI 清单加总，最确定——先算
2. **住宿**：晚数×档位单价。档位写区间不写具体酒店价
   （"中档 300-500/晚"，不许写"XX 酒店 388 元"——那是实时价格，我们不承诺）
3. **交通**：往返大交通按"约 X 元（以官方平台实时查询为准）"估；
   当地交通按天×人均市内交通估
4. **餐饮**：天数×餐标。餐标分三档：经济 50-80/天、舒适 100-150/天、享受 200+/天
5. **购物**：可选，用户不提就写 0 或不列
6. **应急预留**：最后算，≥5%，单独列——不许和"其他"合并，合并了等于没有

每项写清"怎么算出来的"（"住宿：3 晚×400=1200"），不许只有一个总数。
没有计算过程的预算表 = 拍脑袋。

## 5. 口径三问（编制前必问）

1. 总预算含往返大交通吗？→ 含和不含差一倍，先问
2. 几个人？→ 人均核算是检验预算靠不靠谱的标尺
3. 什么消费档位？→ 经济/舒适/享受，直接决定住宿和餐饮两项

不问口径直接估，估出来一定是错的——错的不是数字，是口径。

## 6. 预算诊断：四个常见病

1. **住宿超标**（>60%）：降一档酒店，或砍 1 天行程——钱要花在体验上，不是床上
2. **无应急**（<5% 或没有）：旅行中一定有意外支出，这是经验不是诅咒
3. **分项对不上总数**：审计 blocker（TV-BUD-001），重算，差 1% 以上就不许交付
4. **缺核心分项**（交通/住宿/餐饮/门票缺 2 项以上）：预算表不完整，实际花费一定超

## 7. 省钱三招（不降低体验）

1. **提前订**：机票提前 3-4 周、酒店提前 2 周，价格通常更友好（"通常"，不是承诺）
2. **错峰**：周末的酒店比工作日贵，能调就调 1 天
3. **住宿降一档**：把住宿从 40% 降到 30%，省下的钱加到餐饮和体验项目上——
   旅行回来你记得的是吃了什么玩了什么，不是床垫什么牌子

## 8. 人均核算（最后的合理性检查）

总预算 ÷ 人数 ÷ 天数 = 人均每天花费。对照：
- <300/天：穷游线，检查餐饮和住宿是不是压太狠了
- 300-800/天：舒适线，大部分国内游落在这里
- >1500/天：享受线，检查是不是住宿超标了

人均每天 <150 元还想住中档酒店——口径错了，回去重问。

## 9. 预算自查表

- [ ] 口径三问已确认（大交通/人数/档位）
- [ ] 六分项齐全（购物可省略）
- [ ] 每项有计算过程
- [ ] 分项求和 = 总预算（误差≤1%）
- [ ] 住宿 ≤60%，应急 ≥5%
- [ ] 价格表述全是"约 X 元（以官方平台实时查询为准）"，无实时承诺
- [ ] 人均每天花费在合理区间

## 10. 反模式

1. **只给总数不给分项**："大概 1 万吧"——没有分项的预算等于没有预算。
2. **把愿望当预算**：总预算 5000，行程按 8000 的排——先砍行程或加预算，二选一。
3. **应急和"其他"合并**："其他（含应急）2000"——花的时候分不清，超了一定先花应急的。
4. **编具体价格**："XX 酒店 388/晚，MU5123 航班 720"——这是实时信息，写了就是承诺，不许。
5. **人均不算**：3 个人 9000 和 1 个人 9000 是完全不同的旅行，不算人均等于没算。

## 11. 特殊场景的预算调整

- **带小孩**：餐饮+20%（小孩吃得少但买得多：零食/奶粉/尿布），门票查儿童优惠（很多景区 1.2 米以下免费）
- **带老人**：交通+15%（多打车少走路），住宿+1 档（电梯房/低楼层是刚需）
- **穷游**：住宿压到 25%、餐饮压到 15%，交通占比会升到 35%——正常，但应急 5% 不许动
- **蜜月/纪念日**：住宿提到 45-50%（体验核心），餐饮提到 25%——这是花钱买记忆的场景，别省错地方
- **出境游**：单独列"签证+保险+电话卡"一项（约 500-1000/人），别塞进"其他"里

## 11.5 预算表的呈现格式

```
## 预算表（3 天 2 人，舒适档）

总预算：9000 元（含往返大交通）

| 分项 | 金额 | 计算过程 | 占比 |
|---|---|---|---|
| 交通 | 2000 | 往返约1500+市内3天约500 | 22% |
| 住宿 | 3600 | 2晚×1800（舒适档） | 40% |
| 餐饮 | 1800 | 3天×300/天/人×2人 | 20% |
| 门票 | 900 | 故宫60×2+天坛15×2+… | 10% |
| 应急预留 | 700 | 总预算8% | 8% |
| 合计 | 9000 | 分项求和=总预算 ✓ | 100% |

> 声明：以上为行程框架估算，机票/酒店实时价格与库存请以官方平台为准自行核实。
```

"计算过程"列是灵魂——没有它，预算表就是拍脑袋；有了它，用户自己就能调。

## 12. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 口径三问确认了吗？→ 没确认回去问。
2. 分项求和=总预算吗？→ 差 1% 以上重算。
3. 住宿≤60%、应急≥5% 吗？→ 超了调结构。
4. 有实时价格承诺吗？→ 有一个就删掉换声明句式。

标准冒烟用例：用本 skill 编一份示例预算表，跑插件自带的
`scripts/audit/travel_audit.py`，确认 TV-BUD-001（求和校验）与
TV-BUD-004（应急预留）不命中（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-travel/issues，
正文写清"输入 → 错误输出 → 期望输出"。占比参考调整请附你的旅行类型。
